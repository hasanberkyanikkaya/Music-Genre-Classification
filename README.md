# Music Genre Classification

Classifies 30-second music clips into 10 genres on the GTZAN dataset, comparing
two approaches: **classical ML on hand-crafted audio features** against a
**segment-based CNN on mel-spectrograms**.

Genres: `blues`, `classical`, `country`, `disco`, `hiphop`, `jazz`, `metal`,
`pop`, `reggae`, `rock`.

## Results

| Model | Test accuracy |
|---|---|
| **CNN** (segment-based) | **0.850** |
| Random Forest | 0.665 |
| SVM | 0.660 |
| KNN | 0.625 |

Per-genre F1 scores are in [`results/model_comparison.csv`](results/model_comparison.csv).
The CNN's best genres are jazz (1.00), classical (0.95) and metal (0.95); the
hardest are rock (0.70) and disco (0.72). Disco is also where every classical
model collapses (F1 0.34–0.47) — it overlaps heavily with pop and hiphop once a
track is reduced to feature means.

### Why the CNN wins by ~19 points

Three things, in order of impact:

1. **Segmentation multiplies the data.** Each 30 s track is cut into ten 3 s
   segments, turning 1,000 tracks into 10,000 training examples.
2. **Spectrograms keep what feature means throw away.** The classical models see
   one 56-dimensional vector per track — every temporal detail averaged out. The
   CNN sees the full 64×64 time–frequency surface.
3. **Majority vote reduces variance.** At test time the per-segment
   probabilities of a track are averaged before taking the argmax, so a few
   misread segments do not decide the track.

## Pipeline

### 1. Feature extraction — `feature_extraction.py`

Downloads GTZAN through `kagglehub` and extracts **56 features per track** into
`data/features.csv` (1,000 rows):

| Feature | Count |
|---|---|
| MFCC means | 40 |
| Chroma means (12 pitch classes) | 12 |
| Spectral centroid, spectral rolloff, zero-crossing rate | 3 |
| Tempo (BPM) | 1 |

`features.csv` is committed, so the classical models can be trained without
re-downloading the audio.

### 2. Classical models — `ml_models.py`

SVM (RBF, `C=10`), Random Forest (200 trees) and KNN (`k=5`, Euclidean) on a
stratified 80/20 split (`random_state=42`), with `StandardScaler` fitted on the
training split only. Writes a confusion matrix per model plus the comparison
plots into `results/`.

### 3. CNN — `cnn_model.py`

Each track becomes ten 3-second segments, each converted to a 64-band
mel-spectrogram resized to 64×64:

```
3 blocks of [Conv2D -> BN -> Conv2D -> BN -> MaxPool -> Dropout]
            widths 32 -> 64 -> 128
GlobalAveragePooling -> Dense(256) -> BN -> Dropout(0.5) -> Softmax(10)
```

Trained for up to 60 epochs (batch 64) with `EarlyStopping` on validation
accuracy (patience 12) and `ReduceLROnPlateau`. `GlobalAveragePooling` is used
instead of `Flatten` to cut parameters and overfitting.

> **The train/test split is done at the track level, not the segment level.**
> Segments of one song are near-duplicates; splitting them across train and test
> leaks the answer and inflates accuracy. `song_level_split()` keeps all ten
> segments of a track on the same side of the split.

### 4. Prediction — `predict.py`

```bash
python predict.py audio_file.wav                 # all four models
python predict.py audio_file.wav --model cnn     # one model
python predict.py audio_file.wav --model all --no-move
```

Classified files are moved into `Classified ones/<genre>/` unless `--no-move`
is passed.

## Setup

```bash
pip install -r requirements.txt
```

Requires `librosa`, `numpy`, `pandas`, `scikit-learn`, `matplotlib`, `seaborn`,
`tensorflow` and `kagglehub`.

## Run

```bash
python feature_extraction.py   # GTZAN -> data/features.csv  (skipped if it exists)
python ml_models.py            # SVM / Random Forest / KNN + plots
python cnn_model.py            # segment dataset, CNN training, track-level eval
```

`cnn_model.py` caches the segment arrays as `data/*.npy` on the first run.
Those caches and the trained weights (`models/*.pkl`, `models/*.keras`) are
**not** in the repository — they are large and regenerated by the commands
above.
